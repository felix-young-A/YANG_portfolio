## A 类 — 知识笔记（Knowledge Field Note）

**定义**：从视频/音频/文章中提取核心观点与结构化知识，生成一份精炼的 Obsidian 笔记。

- **触发词**：总结、提炼、知识点、做笔记、知识库、有价值、方法论、机制、框架、复盘、整理成 Field Note、帮我学会、抓住重点
- **输出格式**：`> [!note]- 摘要` 折叠块 + 多级标题正文
- **内容来源优先级**：字幕 > 音频转写 > 网页正文
- **处理目标**：先尽量获取完整视频音频/字幕，再基于内容做二次加工，提炼可复用的知识文档
- **输出重点**：
  - 保留原视频的核心论证和案例，把零散口语整理成稳定的知识结构
  - 提炼机制、方法论、判断标准、流程、坑点、适用边界，而不是泛泛总结
  - 遵循“通读提主线 → 识块定框架 → 章节贴论点 → 填充与金句化 → 节奏打磨”五步流程（详见 [writing-standards.md](writing-standards.md) 的 A 类写作标准）
  - 章节用编号 + 判断式小标题组织，让读者只看标题就能串起逻辑
  - 可复用结论提炼成金句独立成段/加粗，每篇控制在 3-6 处
  - 不要离开原视频自行发挥；`Full Transcript` 区域放“基于转写内容整理的知识笔记”，不必逐字还原
  - 必须在说明里标注依据：公开字幕、音频转写、页面章节，或用户提供正文
- **默认**：用户给视频链接并说“总结一下”“做笔记”“放知识库”，就走 A 类

## B 类 — 原生文稿（Native Transcript）

**定义**：将视频或音频的语音内容完整转写为逐字文稿，保留原始语序和完整性。

- **触发词**：原文稿、完整文稿、逐字稿、转写稿、字幕、把文稿整理出来、按视频内容排版、不要总结、保留原话
- **输出格式**：按时间轴或章节分段的纯文本，不删减、不改写
- **内容来源**：**音频转写是强制步骤**（见 [transcription.md](transcription.md) 的“音频转写判定规则”）
- **输出重点**：
  - 尽量保留视频原话和表达顺序（信息守恒：核心内容不删减、不改写）
  - 修正明显错字、同音误识别、断句、标点、段落，但不替作者重写
  - 段落按语义及内容结构进行切分，避免一行一句或巨大段落
  - 可以加少量小节标题帮助阅读，但不要把原文改写成知识文章
  - 小节标题用概括式短句，不加“综上所述”等 AI 腔调
  - 不要加入视频里没有的信息
  - `Full Transcript` 区域放整理后的原生文稿
- **默认**：用户明确要“文稿/逐字稿/原文稿”时，走 B 类

## C 类 — 网页清理（Web Article Cleanup）

**定义**：对微信公众号文章、小红书图文、博客等网页内容进行去噪清洗，输出干净的 Markdown。

- **触发词**：公众号、网页、文章、博客、新闻、清理、排版、去广告、整理正文、剪藏
- **输出格式**：去除导航、广告、推荐模块后的纯净正文 Markdown
- **内容来源**：Defuddle / Readability / 直接抓取
- **输出重点**：
  - 抓取标题、作者、来源、日期、正文
  - 去除广告、二维码、关注引导、相关推荐、分享按钮、版权噪音、跟踪链接、重复元数据
  - 保留原文主要结构和观点，不改变原文立场
  - 优化段落、标题层级、标点和排版：段落控制在 2~4 句，超过 5 行拆分，标题层级清晰
  - 清理过程中如需要写说明文字，遵循去 AI 味规则（见 [writing-standards.md](writing-standards.md) 的 C 类清理标准）
  - 如果用户要求知识笔记，可以额外增加 `Abstract` 和 `Key Points`（按 A 类提炼标准）；否则以清理后的 `Content` 为主
- **默认**：链接是微信公众号、网页文章、博客、新闻页，且用户没有要求“总结方法论”，就走 C 类
